# Historical large-model benchmark — 2026-11-01

Machine: Intel Core i7-12700 (20 logical processors), Windows 11, .NET 10.0.14, BenchmarkDotNet 0.14.0. One launch, three warmups and six 200 ms measurement iterations per case. Short microbenchmark results are noisy and do not establish end-to-end application throughput.

This file is a historical baseline captured before the production `DbContext` gained its instance-level model cache (and before the current DbSet cache/lease implementation). Do not read the `current model path` rows as evidence that today's path rebuilds an uncached model. The generated fixture has 100 or 300 entities with two properties. `Fluent=true` configures a comment for every entity; `Fluent=false` has no Fluent entity configurations. Each measurement accesses one, ten, or all distinct sets. The legacy cache candidate holds the resolved model only for the current context and is retained for historical comparison. A new context is constructed and synchronously disposed for the first two methods; all methods share a data source and never open a database connection. This does not measure DI scope costs, SQL generation, startup, network, PostgreSQL, or materialization.

The prewarmed reuse and queue prototypes retain an already-used context and its DbSets. Neither performs production-required state reset, lease validation, user-state isolation, rollback or contention; the queue is measured with a single thread. Their allocations do not include retained pool memory, so these numbers are optimistic and are not measurements of the current safe production context pool. Use `DbContextPoolBenchmarks` for the real `AddDbContextPool` versus `AddDbContext` scope comparison. Timings are environment-specific; compare distributions and allocations, and repeat on the target workload.

This historical uncached baseline cannot be reproduced with the current production model cache enabled. The fixture can still be rerun to measure current code; see the benchmark README for filtering.
